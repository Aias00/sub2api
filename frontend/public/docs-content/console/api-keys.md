# API 密钥

API 密钥是 cloudbase 控制台里最核心的用户对象之一。你真正给客户端配置的，通常不是账号密码，而是这里创建出来的 Key。

## 什么时候应该新建 Key

建议按用途拆分，而不是所有工具共用一个：

- 本地开发一个 Key
- 自动化脚本一个 Key
- 团队共享工具一个 Key
- 临时测试一个 Key

这样做的好处：

- 出现异常时可以单独停用
- 更容易看清哪类工具在消耗额度
- 不需要因为一个客户端泄露而整体更换所有配置

## 创建 Key 时最重要的选项

### 名称

名称建议直接写用途，例如：

- `claude-code-local`
- `codex-repo-bot`
- `team-shared-cherry`

### 分组

Key 绑定的分组决定它：

- 能访问哪些模型
- 使用哪个平台
- 按什么倍率计费

如果不确定该选哪个，先去看 [可用分组](./available-groups)。

### 过期时间 / 配额 / IP 限制

这些字段适合在下面场景使用：

- 给外部协作者临时发一个 Key
- 给自动化任务设单独预算
- 只允许某台机器或某个网络出口使用

## 创建后下一步做什么

创建 Key 后，建议立刻去：

1. **调用说明**：拿 Base URL、认证头、示例
2. **可用分组**：确认这个 Key 背后的能力范围
3. **使用记录**：验证是否真的走到了 cloudbase

## 常见使用建议

### 不要把同一个 Key 同时给太多工具

否则你后面看到一堆混合请求时，很难知道：

- 到底是哪一个客户端在消耗
- 哪个工具配置错了
- 哪个模型对应哪类场景

### 复制 Key 后立即保存

很多系统只在创建瞬间完整展示一次。  
如果你依赖浏览器历史再回头找，容易丢失。

### 不要把 Key 提交到仓库

即便是私有仓库，也不建议：

- 写进代码
- 写进公开截图
- 写进共享文档正文

## 遇到问题时先检查什么

- Key 是否已停用
- Key 是否绑定了正确分组
- 客户端是否真的用了这个 Key
- Base URL 是否来自控制台最新调用说明
- 请求是否打到了当前站点而不是旧 Provider
