# 可用分组

“可用分组”页面展示的是：**当前账号此刻可以实际使用的分组目录**。  
它不是系统全量分组列表，而是和你的权限、订阅、管理员授权直接相关的结果。

## 为什么这个页面重要

很多用户以为“模型列表看不到”是客户端问题，实际上更常见的原因是：

- 账号当前没有对应分组权限
- 当前 Key 绑定到了不同分组
- 订阅型分组还没生效

所以在配置客户端之前，先看“可用分组”通常最省时间。

## 页面里会看到哪些分组

### 公开分组

这类分组通常：

- 对所有用户开放
- 适合作为默认接入入口
- 用来承载常见模型或基础能力

### 专属 / 订阅分组

这类分组通常来自：

- 管理员单独授权
- 某个订阅套餐
- 某类更高等级能力入口

你只能看到**自己已经有权访问**的这部分，不会看到系统里全部隐藏分组。

## 分组决定什么

一个分组通常会影响：

- 平台类型（如 Claude / GPT / Gemini）
- 倍率
- 额度限制
- 某些附加能力，比如图像相关支持

## 和 API Key 的关系

你创建 API Key 时，真正要选的就是这里的分组。  
也就是说：

- **可用分组** 告诉你“你能选什么”
- **API 密钥** 告诉你“你最终绑定了什么”

如果某个 Key 调不到你预期的模型，先检查：

1. 这个 Key 当前绑定的分组
2. 这个分组是否还在你的可用列表里

## 什么时候要回来看这个页面

- 你刚买完订阅或充值后
- 管理员说已经给你开通了某个能力后
- 某个工具突然看不到之前能用的模型时
- 你准备给不同工具分配不同 Key 时

## 最实用的用法

如果你不确定如何分配 Key，可以先按下面方式：

- 一个 Key 绑定最稳妥的公开分组
- 一个 Key 专门绑定更高能力或订阅分组

这样你能把“日常开发”和“高成本/高能力请求”分开管理。
