API Key 是客户端访问平台的最小授权单元。

## 创建建议

- 一把 Key 对应一个项目或一个环境。
- 不要让多个独立系统共享同一把生产 Key。
- 命名时带业务含义，后续查日志和回收会轻松很多。

## 分组绑定的意义

Key 真正能调用什么，不只取决于 Key 本身，还取决于它绑定的分组。

分组会影响：

- 可用模型范围
- 路由策略
- 价格倍率
- RPM 或其他限流配置

## 轮换策略

建议在以下场景主动轮换：

- 密钥疑似泄漏
- 项目交接
- 测试环境切换
- 第三方服务商变更

轮换步骤通常是：

1. 新建一把 Key
2. 把调用方灰度切过去
3. 确认新 Key 稳定
4. 回收旧 Key

## 安全建议

### 不要把 Key 写死在前端源码

浏览器前端、公开仓库、移动端包体都不适合直接放生产 Key。

### 给不同调用方分开密钥

这样你可以：

- 单独禁用问题调用方
- 快速定位异常流量来源
- 分项目统计真实成本

### 定期检查使用记录

如果某把 Key 的请求量、Token 或模型分布突然异常，优先排查调用源是否发生变更。
