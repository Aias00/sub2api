统一网关是平台最核心的对外能力。

## 调用说明页会给你什么

当你在 `调用说明` 页面选择一把 API Key 之后，平台会按这把 Key 当前绑定的分组生成：

- 统一网关地址
- 推荐鉴权头
- curl 调用示例
- 对应模型平台的接入说明

## 调试时的最小闭环

建议始终按这个顺序排：

1. Key 是否有效
2. Key 是否绑定到了正确分组
3. 分组里是否有目标模型或上游渠道
4. 余额、订阅或限流是否触发

## 常见请求头

```http
Authorization: Bearer sk-xxxx
Content-Type: application/json
```

某些上游或网关模式下，平台还可能要求额外头信息。以调用说明页里当前 Key 生成的内容为准。

## 推荐的联调方式

### 先用 curl

curl 能最直接排掉前端 SDK、代理层和跨域等干扰。

### 再接 SDK

当 curl 已经确认能通，再接 OpenAI 兼容 SDK、前端应用或 Agent 框架。

## 排障建议

### 模型不存在

- 当前分组没有该模型
- 模型名和平台映射不一致
- 上游账号或渠道尚未激活

### 请求成功但结果不符合预期

- 实际命中的渠道与你想象的不一样
- 分组倍率、调度或兜底模型生效了
- 上游返回已被兼容层转换

### 偶发失败

- 上游渠道波动
- 账号被限流
- 某一条路由临时不可用

这类问题建议结合 `渠道状态`、`使用记录` 和管理员侧的渠道监控一起看。
